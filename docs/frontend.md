# Frontend, certificates and DNS

The final root configuration wires the ALB instance target group to the ASG, enabling ELB health checks. CloudFront uses a separate origin hostname, a custom viewer alias and two validated ACM certificates. This is configuration and plan evidence only. No DNS zone/domain has been supplied, no certificate has been issued, and no HTTPS handshake has been tested.

## TLS and origin restrictions

| Connection | Configuration |
|---|---|
| Viewer → CloudFront | Custom site alias, viewer certificate in us-east-1, TLSv1.2_2021 security policy, HTTP redirected to HTTPS |
| CloudFront → ALB | Origin domain matches the regional certificate; HTTPS-only, TLS 1.2 |
| ALB → EC2 | HTTP port 80 inside the private VPC; explicitly not encrypted at this hop |
| EC2 → RDS | MySQL TLS required; client verification flags and CA trust configured |
| EC2 → EFS | NFS through TLS-enabled EFS mount helper and IAM access point |

The ALB uses `ELBSecurityPolicy-TLS13-1-2-2021-06`, confirmed by a read-only AWS lookup to support TLS 1.2 and TLS 1.3. The ALB accepts HTTPS only from CloudFront's origin-facing managed prefix list. Its default listener action is 403; a request must also contain the private header value generated by Terraform's `random_password` resource before it can reach the target group.

The header value is sensitive and is never exposed as an output. It is an origin access credential and will exist in state and private saved plans after deployment. Restrict state storage and access, and rotate it deliberately across both listener and distribution. The prefix list alone does not identify this distribution.

The ALB DNS name itself cannot be used as the CloudFront HTTPS origin because the issued certificate covers the owned origin DNS name. The dynamic origin request policy excludes viewer `Host`; CloudFront sends the origin hostname instead. Other viewer headers (including authorization-related headers), cookies and query strings are forwarded. WordPress canonical URLs use the configured public site URL, and ALB supplies the HTTPS forwarded-proto header.

## Cache and security headers

Default/dynamic cache TTLs are zero. All seven supported HTTP methods are allowed, preserving login, admin, AJAX and REST writes. Selected public uploaded images (`jpg`, `jpeg`, `png`, `gif`, `webp`, `avif`) use ordered behaviors with a one-day default TTL, zero minimum TTL and seven-day maximum TTL. Query strings are included in the image cache key; cookies are not. Error-cache minimum TTLs are zero for supported 4xx/5xx error codes.

The image behaviors assume the standard WordPress public media model. Disable or redesign these behaviors before adding a plugin that protects or personalizes uploaded images. Not all `wp-content` paths are cached. Replacing an image at the same URL can require a CloudFront invalidation or a versioned URL.

The response-header policy adds nosniff, strict-origin-when-cross-origin referrer policy and one-year HSTS without subdomain/preload scope. SAMEORIGIN framing is supplied only when the origin does not already send a stricter header. A site-specific CSP is not asserted without testing WordPress/admin/plugin behavior. WAF, Shield Advanced enrollment and CDN/ALB request-access logging are not provisioned in this assessment; they remain production hardening/visibility decisions. Retained RDS/Lambda logs and account CloudTrail configuration do not replace HTTP access logs.

## DNS modes and deployment prerequisites

Defaults `https://school.example.com`, `origin.example.com` and `admin@example.com` are explicit plan-only examples. They do not represent domains owned by the applicant. A successful plan does not validate ownership, issuance, resolution or TLS connectivity. Obtain two names under an owned public domain and choose the correct administrator email before any deployment. The site and origin names must differ.

### Existing public Route 53 zone

Set `hosted_zone_id` to the existing public zone covering both names. Terraform creates both ACM validation CNAMEs, an ALB origin A-alias, and CloudFront site A/AAAA aliases. Wait for certificate issuance and distribution propagation before runtime tests. Do not create an unrelated/private zone and assume it authorizes public ACM validation.

### External DNS

Leave `hosted_zone_id = null`. Terraform requests the certificates and waits for DNS validation, but creates no Route 53 records. Use this staged preparation only after choosing owned names and reviewing a certificate-only plan:

```powershell
terraform plan -target=module.certificates.aws_acm_certificate.origin -target=module.certificates.aws_acm_certificate.viewer '-out=.private/certificates.tfplan'
terraform apply .private/certificates.tfplan
terraform state show module.certificates.aws_acm_certificate.origin
terraform state show module.certificates.aws_acm_certificate.viewer
```

The two targeted certificate requests are an exceptional prerequisite step so the external CNAMEs can be obtained before a full deployment. Publish the exact validation CNAME names/values in the external DNS provider; keep them for renewals. Wait for both certificates to become issued in their respective regions. Then regenerate and review an untargeted full plan before applying it. Do not reuse the submitted placeholder-domain plan for deployment.

After the ALB and distribution exist, create the external origin CNAME to `website.alb_dns_name` and the site CNAME to `website.distribution.domain_name`. The site must use a subdomain when the DNS provider does not support apex aliases/flattening. The external origin DNS record cannot be enforced by Terraform, so verify its resolution before testing requests; otherwise CloudFront can return origin DNS/TLS errors.

## Health and remaining runtime checks

The target group is type `instance`, HTTP/80, checking `/health.php` for HTTP 200. It uses 30-second checks, two healthy checks, three unhealthy checks, and a 120-second deregistration delay. The ASG uses ELB health checks and a 900-second startup grace. Runtime bootstrap duration, instance refresh behavior and health replacement still need testing.

Review `docs/test-plan.md` before deployment. Runtime evidence is NOT RUN; the current deliverable uses the test's permitted Terraform-plan route and discloses the DNS prerequisites.
